# Security Policy

Security is a core requirement of Ivadoo.

## Reporting a vulnerability

Please do not report security vulnerabilities through public GitHub issues.

When possible, use GitHub's private vulnerability reporting or contact the Ivadoo maintainers privately through the KGS-L organization.

Include enough information to reproduce and evaluate the issue, such as:

- affected component or module;
- affected version or commit;
- reproduction steps;
- expected and observed behavior;
- potential security impact;
- proof of concept when appropriate.

Please avoid accessing, modifying or exposing data that does not belong to you while investigating a vulnerability.

## Security scope

Particular attention is given to:

- organization and tenant isolation;
- role and permission enforcement;
- company and establishment data boundaries;
- authentication and session security;
- sensitive documents, measurements and photos;
- inventory and financial operations;
- audit trails;
- API credentials and secrets;
- backups and deployment infrastructure.

## Disclosure

Please allow the maintainers reasonable time to investigate and prepare a fix before publicly disclosing a vulnerability.

A more detailed vulnerability disclosure process will be introduced before the first production release.
